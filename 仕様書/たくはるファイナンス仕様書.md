## 4. データ構造（Firestore）

### 4.1 コレクション構成

```
users/{uid}
  ├─ householdId: "TAKUHARU"
  ├─ name: String（表示名）
  └─ fcmTokens: [String]（FCMトークン）

households/TAKUHARU（固定）
  ├─ members: [uid, uid]
  ├─ memberNames: {uid: "たく", uid: "はる"}
  ├─ memberIcons: {uid: "🐻", uid: "🐰"}
  ├─ paymentMethods: ["現金", "クレジットカード", ...]
  ├─ personalFoodBudgets: {uid: 8000, ...}（個人食費わく・月上限）
  ├─ replacements: [{"from": "...", "to": "..."}]（OCR辞書）
  ├─ customExpenseCats: ["カスタムカテゴリ"]
  ├─ customIncomeCats: [...]
  └─ monthlyBudget: int?（月予算・null=未設定）

  ├─ transactions/{id}      # 取引
  ├─ plan_items/{id}        # プランニング
  ├─ subscriptions/{id}     # 固定費・サブスク
  └─ special_expenses/{id}  # 特別支出（旅行など・v0.2.112〜）
```

### 4.2 Transaction（取引）型定義

```dart
class Transaction {
  final String id;                  // ドキュメントID
  final DateTime date;              // 取引日
  final TransactionType type;       // expense / income / transfer
  final Category category;          // {major, sub}
  final String paymentMethod;       // "現金" 等
  final String description;         // 内容・摘要
  final int amount;                 // 金額（円・税込・常に正）
  final String? receiptUrl;         // Drive リンク
  final String? receiptId;          // 親レシート参照ID（OCR取込時）
  final String? memo;               // 備考・品目リスト
  final String? store;              // 店舗名
  final String? originalCurrency;  // "USD" 等（null=JPY）
  final double? originalAmount;    // 元通貨での金額
  final String? transferFromAccount;
  final String? transferToAccount;
  final bool isPending;             // 見込みフラグ（発生主義）
  final String? recordedBy;         // 記録者UID
  final String? paidBy;             // 支払者UID（割り勘用）
  final String? personalFor;        // 個人食費わく対象UID
  final int commentCount;           // チャット件数（読み取り専用）
  final DateTime? createdAt;        // 登録日時（初回保存時のみセット・編集で不変）
  final UsageDetail? usage;         // 使用量メタ（水道検針票・v0.2.105〜／金額集計に非関与）
  // Firestore: households/TAKUHARU/transactions/{id}
}

enum TransactionType { expense, income, transfer }

/// 使用量メタ（検針票の非金額データ・v0.2.105〜）。
/// 金額の内訳は品目Transactionで持つので、ここは m³ 等のメタに絞る。
class UsageDetail {
  final double? amount;      // 今回使用量（例 31）
  final String unit;         // 'm3' / 'kWh'（水道は 'm3'）
  final double? prevAmount;  // 前年同期の使用量（例 32）
  final DateTime? periodFrom;// 使用期間 開始
  final DateTime? periodTo;  // 使用期間 終了
  final String kind;         // 'water'（将来 'electricity' / 'gas'）
}
```

**登録日時 `createdAt`（v0.2.100〜）**
- 初回保存（`TxRepository.add` / `addAll`）でのみ `DateTime.now()` のローカルISO文字列を書く。
  編集（`update`・merge保存）では触らないので「いつ登録したか」が保たれる。
- 明細の詳細（`TransactionChatScreen`）とレシート詳細（`ReceiptDetailScreen`）のヘッダーに
  `_infoRow('登録', …)` として小さく表示。`createdAt` が無い取引では行ごと省略。
- 既存データ（v0.2.100より前）は `createdAt` を持たないため、`updatedAt`（サーバー書込時刻）から
  一度だけ後付けした（`scripts/backfill_takuharu_created_at.py`・冪等）。一度も編集していない取引は
  登録時刻そのもの、編集済みは最後に直した時刻の近似になる。

### 4.4 Subscription（固定費・サブスク）

```dart
class Subscription {
  final String id;
  final String name;              // "Netflix"
  final int amount;               // 目安金額
  final String category;          // "趣味・娯楽"
  final String frequency;         // "monthly" / "yearly"
  final int? yearlyMonth;         // 年払い時の月（1-12）
  final int? payDay;              // 支払日（1-31）
  final String? paidBy;           // 支払者UID
  final bool active;
  final bool variable;            // 変動費フラグ（水道光熱費等）
  final Map<String, int> monthlyActuals; // {"2026-06": 5400}
  // Firestore: households/TAKUHARU/subscriptions/{id}
}
```

**固定費の自動記帳（v0.2.101〜）**: アプリ起動時・復帰時に `SubscriptionAutoRecord.run()`
（`lib/data/subscription_auto_record.dart`）が走り、**支払日（payDay）が来た今月分の固定費を
自動で支出に記帳**する。手動の「今月分を支出に記録」ボタンと同じ receiptId
`sub-{id}-{YYYYMM}` を使い、さらに自動記帳はドキュメントIDも receiptId にするため、
手動・自動・2台同時起動のいずれでも**二重計上にならない**（冪等）。
ルール: ①payDay 未設定は月初(1日)扱い ②変動費はその月の実額が入力されるまで記帳しない
③金額0は記帳しない ④復帰連打は10分間引き。

### 4.5 SpecialExpense（特別支出・v0.2.112〜）

`households/{hid}/special_expenses/{id}`。**旅行・引っ越しなど「日をまたぐまとまった出費」を束ねる箱**。
箱自体は金額を持たず、金額は取引側の `specialExpenseId` でぶら下がる。

| フィールド | 型 | 意味 |
|---|---|---|
| `id` | String | ドキュメントID |
| `name` | String | 表示名（例「仙台・松島旅行」） |
| `kind` | String | 種類。旅行／おでかけ／ライブ・イベント／引っ越し／家電・家具／冠婚葬祭／医療／その他 |
| `start` | String(ISO) | 期間のはじまり |
| `end` | String(ISO)? | 期間のおわり（null=未定） |
| `settled` | bool | 精算済みか（true=一覧の「精算が済んだもの」へ落ちる） |
| `memo` | String? | 備考 |

Transaction 側の追加フィールドは2つ。

- `specialExpenseId`（String?）… どの特別支出にぶら下がるか。**月をまたいでも1つの箱として集計できる**
- `isPending`（bool・finance_core に既存）… **予定＝予約済みだがまだ払っていない**

🔥 **予定（`isPending=true`）は `TxRepository.watch()` が流さない。**
まだ財布から出ていない金額を月の支出・予算・分析・カレンダーに混ぜると、
使ってもいない金額で予算が溢れて見えるため。予定が見えるのは特別支出の詳細画面だけ
（そちらは `watchBySpecialExpense()` で別に引く）。当日払ったら
「予定◯件を払った」でまとめて確定にすると、その月の支出に現れる。

**精算の出し方**（`SpecialExpenseSummary`）
1. 確定分だけを対象にする（予定は精算しない＝まだ動いていないお金だから）
2. 支払者（`paidBy ?? recordedBy`）ごとに立替額を足す。
   支払者が null／`both`（一緒に払った）はその場で折半済みとみなし、精算に含めない
3. 立替が起きた合計を人数で割ったものが1人の自己負担。
   立替額との差がプラスの人が受け取り、マイナスの人が渡す
4. 「◯◯が◯◯に ¥X わたすと精算」を1行で出す

## 5. 認証・世帯共有の仕組み

### 5.1 認証フロー

```
AuthService.signInWithGoogle()
  → Android: GoogleSignIn.authenticate() → Firebase
  → Web: FirebaseAuth.signInWithPopup(GoogleAuthProvider)
  → HouseholdService.ensureHousehold(user)
      → households/TAKUHARU の members に uid を追加
      → 旧データがあれば _migrateData() で移行
```

### 5.2 世帯共有のポイント

- 世帯ID は **`TAKUHARU` 固定**（コード入力不要・ログインするだけで参加）
- `recordedBy: uid` で「誰が記録したか」を識別
- `paidBy: uid` で「誰が払ったか」を識別（割り勘用）
- `personalFor: uid` で「誰の個人食費わくか」を識別

### 5.3 Firestore セキュリティルール（概要）

- `users/{uid}`: 本人のみ読み書き
- `households/TAKUHARU` および配下: `members` に含まれるユーザーのみ

## 6. カテゴリ体系

### 6.1 支出カテゴリ（既定・15種類）

```
食費, 外食, Uber, 日用品, デート, 住居, 光熱費, 通信,
交通, 趣味・娯楽, 衣服・美容, 医療・健康, 交際費, 特別費, その他
```

- 各カテゴリにアイコン（Material Icons Rounded）＋パステルカラー
- カスタムカテゴリは名前からハッシュで色を自動生成
- 世帯で共有（`customExpenseCats` に追加）
- **Uber は v0.2.103 で追加**（Uber Eats 等・delivery_dining アイコン）

### 6.1.1 カテゴリの管理（設定＞カテゴリ／v0.2.103〜, v0.2.104で刷新）

- 設定画面に「**カテゴリ**」タブ（サイドバー2番目）。支出／収入を切り替えて管理する。
- **v0.2.104〜：既定とカスタムの区別をなくし、1本のリストで表示**（リスト形式）。
  - **並び替え**：各行右の ≡ ハンドルをドラッグ。順番は `expenseCatOrder`/`incomeCatOrder`
    （名前の配列）としてFirestoreに保存し、**記録画面・レシート・サブスク・OCR候補の
    カテゴリ並びにも反映**される（`HouseholdService.orderedCategoryNames / orderedCategories`）。
  - **削除（×）**：カスタムは完全削除（`customExpenseCats`等から除去）、既定は「非表示」
    （`hiddenExpenseCats`/`hiddenIncomeCats`）にする。どちらも選択リストから消えるが、
    **これまでの記録の金額・内容・カテゴリ名は変わらない**。
  - 非表示にした既定カテゴリは、フッターの「消したカテゴリ」チップをタップで復元。
  - **追加**：「カテゴリを追加」。表示中の名前と重複なら追加しない。消した既定と同名を
    追加すると自動で復元する（`addCustomCategory` が hidden を解除）。
- 実装（`HouseholdService`）：`orderedCategoryNames/orderedCategories`（統合＋並び＋非表示適用）、
  `setCategoryOrder`・`deleteCategory`・`restoreCategory`・`addCustomCategory`・`removeCustomCategory`。

### 6.1.2 個人の食費わくONで「共用食費」へ自動切替（v0.2.104〜）

- 記録画面で「**🍙 個人の食費わくから引く**」トグルをONにすると、カテゴリを自動で
  「**共用食費**」（`sharedFoodCategory` 定数）に切り替える。共用の食費わくから買ったものだと
  一覧で見分けられるようにするため。
- 「共用食費」は `personalFoodCategories` に含めてあり、トグルの表示条件（食費・日用品・共用食費）
  を満たすので、切替後もトグルは出続ける。存在しなければ自動でカスタム追加する。
- 個人わくの集計は従来どおり `personalFor`（誰のわくか）だけで合算するので、カテゴリが
  「共用食費」でも金額はそのわくにきちんと乗る。

## 9. 収支入力の仕様

### 9.1 入力方式

1. **手入力** → `AddTransactionScreen` でフォーム入力
2. **レシート読取** → Gemini Vision API でOCR → 品目ごとか1件まとめかを選択

### 9.2 個人食費わく

- **対象カテゴリ（v0.2.91〜）**: 「食費」に加えて「日用品」も個人の食費わくに入れられる
  （レジ袋など食費と一緒に買う日用品が入ることがあるため）。判定は `categories.dart` の
  `isPersonalFoodCategory()`／`personalFoodCategories = {'食費','日用品'}` に集約し、登録画面・
  レシート品目記録・まとめ編集の各所で共通利用する。予算集計（ホームの個人食費わくカード）は
  カテゴリで絞らず `personalFor` だけで合算するので、日用品を入れても自動で反映される。
- 支出に `personalFor: uid` を付与 → その人の個人わくから引かれる
- 同時に世帯支出合計にも含まれる（共用財布から出る・個人の食費として記録）
- 月上限: `personalFoodBudgets[uid]`（既定 8,000円）
- **わくは常に「ログイン中の自分」のもの（v0.2.84〜）**: 相手のわくには入れられない。
  各画面で `personalFor` をセットするときは必ず自分の uid を使う（`_payer`/`_paidBy` ではない）。
  これにより「相手の食費わくを勝手に消費する」ことが起きない。
- **登録画面**: カテゴリで「食費」または「日用品」を選ぶと、カテゴリのすぐ下に目立つトグル
  「🍙 個人の食費わくから引く」が出る（v0.2.79〜／対象拡大 v0.2.91〜）。
  ラベルは自分の名前・自分の月わくを表示（v0.2.84〜）。相手のわくに入っている記録を
  編集すると「今は ◯◯ の個人わくに入っています（このトグルは自分のわく用です）」と注記し、
  自分の操作では相手のわくを外さない（`_resolvePersonalFor`）。
- **明細画面は表示だけ（v0.2.84〜）**: 食費の支出の明細を開くと、付いている場合は
  「◯◯ の個人の食費わくから」タグを表示するのみ。設定・変更・解除のボタンは廃止。
  付け外し・変更は**編集画面**で行う（明細からは操作しない）。
  ※旧「個人の食費わくに入れる／相手のわくに変更／はずす」ボタンは削除した。
- **レシート品目画面の一括設定（v0.2.84〜 / v0.2.85でチップ化）**: レシート読み取り後の
  「品目ごとに記録」（`ReceiptSplitScreen`）と「レシートを編集」（`ReceiptEditScreen`）で、
  食費の品目をまとめて個人わくに入れられる。**「品目（X件）」見出しの右隣に小さなチップ
  「🍙 ぜんぶ個人わく」**を置き、タップで全食費品目をON/OFF（個別カードのトグルと連動・
  全部ONならピンクに点灯）。わくは自分のもの。
  ※v0.2.84は全幅の大きいトグルだったが、見た目が重いため小さなチップに変更（v0.2.85）。
- **支出の記録カードの「個人」バッジ（v0.2.109〜）**: 支出タブの「支出の記録」一覧で、
  `personalFor` が付いた（＝個人わくの）支出は、カードの副題（日付＋カテゴリ／🧾まとめ）の
  **右隣に小さなピンクのバッジ**を出す。名前が引ければ「たく個人」「はる個人」、引けなければ
  「個人」。単品カード（`_tile`）と まとめカード（`ReceiptGroupTile`）の両方に対応し、
  まとめは中の品目に1つでも個人わくがあればその人のバッジを出す。バッジ本体は
  `receipt_group.dart` の共通関数 `personalScopeBadge(uid)`。一覧を開いた瞬間に
  「これは誰かの個人わくの支出だ」と一目で分かるようにするための目印（表示のみ・操作はしない）。

### 9.2.2 水道料金レシート＋使用量の内訳（v0.2.105〜）

水道（上下水道）の検針票・請求書を、既存のレシート撮影フロー（`ReceiptFlow` → OCR →
`ReceiptSplitScreen`）でそのまま登録できる。専用の導線は増やさない。

- **OCR（`receipt_ocr.dart`）**: プロンプトに `water` ブロックを追加。水道と判定すると
  `isWaterBill=true` にし、品目を **「水道料金」「下水道使用料」の2件**（各カテゴリ＝**光熱費**）、
  `amount`＝ご請求金額（税込合計）、`store`＝「水道料金」として返す。加えて **使用量メタ**
  （今回使用量 m³・前年同期 m³・使用期間 from/to）を `ReceiptResult.usage`（`UsageDetail`）に載せる。
  - **名古屋市様式は左右2枚**（左＝今回の「水道ご使用量のお知らせ」／右＝前回分の「上下水道料金
    領収書（口座振替払用）」）で金額・期間が異なる。**必ず左の「今回ご請求金額」側**を使うよう
    プロンプトで明示（右の領収書＝前回分の振替金額は使わない）。
  - 使用量は m³ の数値であり、指示値（135/104 等）や料金・消費税額と混同しない。和暦は西暦へ。
  - **取引日（date）は「検針日」を採る**（無ければ発行日／受取日→使用期間の終了日）。**「口座振替日」は使わない**（v0.2.106〜）。引き落とし日を取引日にすると翌月扱いになり、登録した月の支出明細から見失う（実際に発生した迷子の対策）。
- **保存**: 使用量メタは、そのレシートの **「水道料金」品目の Transaction にだけ** `usage` として
  紐づける（金額は品目Transactionのまま＝ホーム・分析・カテゴリ内訳などの**既存集計にそのまま乗る**。
  `usage` はメタ情報で**金額集計には一切関与しない**）。
- **UI**:
  - `ReceiptSplitScreen`（初回登録）／`ReceiptEditScreen`（再編集）: 水道と判定されたときだけ
    **「💧 水道の使用量」カード**を出す（今回使用量・前年同期・使用期間 from/to を編集可）。
  - `ReceiptDetailScreen`（詳細）: 内訳の下に **`💧 使用量 31m³（前年 32m³（▲1m³））／期間 …`** を表示。
- **将来拡張**: `UsageDetail.kind` に `electricity`/`gas` を足せば同じ器で電気・ガスに拡張できる。
  使用量の月別推移グラフは、`usage != null` の取引を月別に拾えば作れる（データを貯める土台済み）。

#### チャットのリプライ（LINE風の引用返信・v0.2.107〜）

- **吹き出しを長押し**するとメニュー（**リプライ** / テキストがあれば **コピー**）が出る。
  メニューは**LINE風に、長押しした指の位置のすぐそばにポップアップで出す**（`showMenu` +
  `onLongPressStart` の `globalPosition`／v0.2.110〜。旧・画面下の `showModalBottomSheet` は廃止）。
  「リプライ」で入力欄の上に引用プレビュー（だれの何に返信するか＋✕で解除）が付き、
  その状態で送るとそのメッセージへの引用返信になる。テキストでも画像でも返信できる。
- 引用は投稿時点の本文を**スナップショットして保存**（非正規化）。元を引き直さずに描け、元が消えても引用は残る。
  コメントドキュメントに `replyToId` / `replyToUid` / `replyToText`（画像のみは空・サムネは `replyToImageUrl`）を持たせる。
  データ表現は `ReplyRef`（`lib/data/comment_repository.dart`）、書き込みは `replyRefToMap`。
- 送信済みの吹き出しに引用ブロック（左に色帯＋だれ＋抜粋）を表示。**引用をタップすると元メッセージへスクロールして一瞬ハイライト**
  （`GlobalKey` + `Scrollable.ensureVisible`）。元が見つからないときは軽く知らせるだけ。
- 対象は `CommentThread`（取引単品チャット・レシートチャット）。変更履歴（`kind='log'`）は会話ではないので長押しメニューを出さない。
  プラン項目チャットは別UIのため今回は対象外（将来同様に拡張可能）。
- Firestore ルールは既存の `comments` 権限のまま（フィールド追加のみ・スキーマ検証なし）で**ルール変更不要**。既存コメントは reply フィールド無しで問題なく読める。

#### チャットのキーボード押し上げ（LINE風・v0.2.108〜）

- 入力欄をタップしてソフトキーボードが出たとき、**チャット欄ごと上に押し上がり、入力バーはキーボードの真上・最新コメントが常に見える**状態にする（LINEと同じ挙動）。
- 押し上げ自体は Scaffold の `resizeToAvoidBottomInset`（既定 true）が担う。`CommentThread` は `Column(Expanded(ListView) + 入力バー)` で、入力バーは**リサイズされる body の中**に置く（`Stack`/`bottomSheet` でオーバーレイしない）ため、キーボード分だけ body が縮んで入力バーがせり上がる。
- それだけだと縮んだ表示域の末尾（最新コメント）が入力バーの裏に隠れるので、`WidgetsBindingObserver.didChangeMetrics()`（キーボード高さ変化）と入力欄のフォーカス取得の両方で、フォーカス中なら**末尾へ自動スクロール**して最新コメントを入力バー直上に保つ。

## 10. OCR レシート読み取り仕様

### 10.1 フロー

```
記録メニュー → "レシートを読取"
  → ReceiptCameraScreen（自前カメラ or ギャラリー）
  → 画像取得（品質55%・最大幅1024px）
  → Gemini gemini-2.5-flash へ base64 送信
  → Drive へ画像を並行アップロード（裏実行）
  → 記録方法を選択（まとめて1件 / 品目ごと）
  → AddTransactionScreen or ReceiptSplitScreen
  → 保存
```

### 10.2 Gemini が返す JSON

```json
{
  "store": "店名",
  "date": "YYYY-MM-DD",
  "amount": 1234,
  "category": "食費",
  "items": [
    { "name": "品名", "price": 500, "quantity": 2, "unitPrice": 250 }
  ]

```

### 10.3 まとめて1件 vs 品目ごと

| モード | 動作 |
|---|---|
| まとめて1件 | 合計金額で1件の支出。品目一覧を memo に記入 |
| 品目ごと | 各品目を独立した支出として記録 |

`ReceiptSplitScreen` の**店名は読み取り結果をテキスト編集できる**（v0.2.82〜。空も可、保存時に全品目へ反映）。

### 10.3.1 税込合計との差額調整（v0.2.86〜）

**背景の地雷**: レシートは常に「品目ごと」に分割記録するため、アプリの合計＝各品目priceの
単純合計になる。一方イオンネットスーパー等の**外税（税抜）レシートは品目が税抜き表記**で、
最下部にまとめて消費税が加算される。OCRは消費税の行を品目に入れない仕様のため、
**品目合計＝税抜小計となり、レシート印字の税込合計と「消費税ぶん」ズレていた**（v0.2.85まで）。
OCRは `amount`（税込最終支払額）を読み取っていたが、分割記録画面では完全に捨てていたのが原因。

**対策（v0.2.86）**: `ReceiptSplitScreen` 下部に**差額調整カード**を追加。
- **レシート合計（税込）**欄に OCR の `amount` をプリフィル（手修正可・未読取時は空欄で手入力可）。
- `差額 = レシート合計 − 品目合計` をライブ表示。
- 差額が 0 でなければ**スイッチ（既定ON）**で、差額を**1件の支出**として自動追加し記録合計を
  レシートとピッタリ合わせる。
  - 差額が正（税込>品目合計）→ 品目「**消費税・調整**」（カテゴリは下記のとおり v0.2.96 で変更）
  - 差額が負（値引き等で品目合計>税込）→ 品目「**値引き・調整**」（金額はマイナス）
  - 同じ `receiptId`・日付・支払元・支払者で追加するので、まとめ行に内包され内訳も残る。
- スイッチOFFなら従来どおり品目合計のまま記録（差額は記録しない）。

**編集画面でも同じ調整（v0.2.87〜）**: `ReceiptEditScreen`（まとめレシートの「レシートを編集」）にも
同じ差額調整カードを追加。**記録済みのレシートを後から税込合計に合わせ込める**。
- 「消費税・調整」「値引き・調整」の品目は**通常の品目リストには表示せず**、差額調整カードで一元管理する
  （`_isAdjustment` で判定して分離）。既存の調整行があれば、レシート合計欄に「全品目＋調整の合計」を
  プリフィルする。
- 保存時：差額があれば既存の調整行を**更新**（無ければ追加）。**差額が0になった／スイッチOFFにすると、
  既存の調整行は自動削除**（`keepIds` に入れない＝`deletes` 対象）。差額調整は通常品目が1件以上
  残るときだけ付く（全品目を空にした「丸ごと削除」には付けない）。
- **差額の品目カテゴリ＝そのレシートの「主たるカテゴリ」（v0.2.96〜）**: 以前は「その他」固定だったが、
  内訳に「その他」が並んで邪魔なので、**そのレシートの品目のうち金額合計が一番大きいカテゴリ**に寄せる
  （食費のレシートなら消費税ぶんも食費）。判定は `categories.dart` の `dominantCategory()`
  （`ReceiptSplitScreen`／`ReceiptEditScreen` の保存時に適用。調整行自身は判定から除外）。
- **過去分の直し（v0.2.96〜／v0.2.97で自動化）**: 既に「その他」で保存済みの調整行を主たるカテゴリへ
  一括で付け替える（`TxRepository.repairAdjustmentCategories`。金額・日付・品名は変更せず、
  何度実行しても安全）。**v0.2.97 からは `MainShell` の起動時に自動実行**（端末ごとに一度きり。
  SharedPreferences `takuharu.adjcat_repaired.v1` で管理し、失敗したら次の起動で再挑戦）。
  設定＞データ＞「消費税・差額のカテゴリを直す」の手動ボタンも残してある。
  ※かつては「Firestore への一括書き換えは開発PCからは実行できない」としていたが、
  **サービスアカウント鍵 `C:\dev\_secrets\takuharu-finance-sa.json` を置いた（2026-07-21）ので
  開発PCから直接直せる**（`scripts/repair_takuharu_adjustment_categories.py`。`--dry-run` あり・冪等）。
- **差額の行も「個人の食費わく」に入れる（v0.2.99〜）**: 以前は調整行の `personalFor` が空のまま作られ、
  **個人わくで買った品目の消費税ぶんだけが共用財布から出ていた**（「相手がいくら使ったか」の合計がズレる）。
  品目の持ち主（`personalFor`）ごとの金額合計を見て、**一番大きい持ち主に調整行を寄せる**。
  判定は `categories.dart` の `adjustmentOwner()`（`dominantCategory()` と同じ考え方の個人わく版）。
  - 共用が一番大きければ `null`＝共用のまま。
  - ⚠ 1レシートに共用と個人が混ざる場合、本来は按分すべきだが、**行を分けると相手に
    「記録したよ」通知が余分に飛ぶ**ので寄せる方式にした（差額は数十円レベル）。
  - 過去分は `scripts/repair_takuharu_adjustment_personal.py` で修正済み（2026-07-21・6件。
    実データに混在レシートは0件だった）。同スクリプトの `split_by_owner()` に按分ロジックが
    入っているので、将来 按分方式へ変えたくなったらそこが起点。

### 10.4 OCR辞書（表記ゆれ置換）

### 12.1 登録・設定

```dart

// 通知色: #FF6B8A（ピンク）

```

### 12.2 タップ時の遷移

| payload | 遷移先 |
|---|---|
| `{type: "tx", txId: "...", receiptId: "..."}` | ReceiptDetailScreen（receiptId 優先・v0.2.94〜） |
| `{type: "tx", txId: "..."}` | TransactionChatScreen |
| `{type: "plan", planId: "..."}` | PlanDetailScreen |

`receiptId` が入っているのはレシートのまとめ通知（→12.4）。`listByReceiptId()` で品目を取り直して
レシート画面を開く。`txId` も併せて送っているので、旧バージョンのアプリでは従来どおり
先頭品目の TransactionChatScreen が開く（後方互換）。

### 12.3 通知の「部屋ごと上書き」＆「開いたら消す」（v0.2.93 で追加）

チャット的な挙動：**同じ取引/プランの通知は1枠にまとまり、その取引/プランを開くと通知が消える**。

- **タグで上書き（送信側 takuharu-notifier `notifier.py`）**: `send(..., tag=...)` で各通知に `tag` を付ける。
  同じ tag は端末側で1枠に上書き（Android=`AndroidNotification.tag`、前面表示=`data.tag`）。
  | 種類 | tag |
  |---|---|
  | 取引の記録/修正 | `tx:<txId>` |
  | レシートの記録/修正（まとめ・→12.4） | `receipt:<receiptId>` |
  | 取引へのコメント | `txcomment:<txId>` |
  | レシートへのコメント（v0.2.98〜） | `receiptcomment:<receiptId>` |
  | プランの追加/更新/完了 | `plan:<planId>` |
  | プランへのコメント | `plancomment:<planId>` |
  | 固定費の追加/変更 | `sub:<subId>` |
  （削除通知は対象の部屋が無いのでタグなし＝個別表示）
- **開いたら消す（アプリ側 `push_service.dart`）**: `TransactionChatScreen`/`PlanDetailScreen`/
  `ReceiptDetailScreen` の initState で `clearForTx(txId)` / `clearForPlan(planId)` /
  `clearForReceipt(receiptId)` を呼ぶ。`getActiveNotifications()` で配信済みを取り、
  該当 tag（`tx:`/`txcomment:`、`plan:`/`plancomment:`、`receipt:`）の通知を
  `cancel(id, tag)` で削除（Androidのみ）。
  - これで「開いたのに通知が残る→手で消す」がなくなる（LINE的）。たくはるカレンダーと同じ設計。

### 12.4 レシートは「1枚＝通知1件」にまとめる（v0.2.94 で追加）

レシートは品目ごとに取引が1件ずつ作られる（`TxRepository.addAll`）ため、素直に通知すると
**品目の数だけプッシュが飛ぶ**（実際に8品目のレシートで8連発していた）。送信側でまとめる。

- **まとめ待ち（`notifier.py`）**: `receiptId` を持つ取引は即送信せず
  `tx_pending[(receiptId, edited)]` に貯め、`threading.Timer` で `RECEIPT_BATCH_SEC`（5秒）待つ。
  品目が届くたびにタイマーを張り直し、**最後の1件から5秒静かになったら1件だけ送る**。
  （Firestoreのbatch commitは通常1スナップショットで届くが、分割して届いても取りこぼさない）
- **文面**: 2件以上 → `「◯◯ がレシートを記録したよ ♡」`／本文 `店名　N品目　-¥合計`。
  1件だけのとき（手入力＋画像の `detail_` レシートなど）は従来どおりの単品文面。
- **編集も同じ**: まとめ編集で複数品目が一度に変わっても `「レシートを修正したよ」` 1件。
  `(receiptId, edited)` をキーにするので「記録」と「修正」は混ざらない。
- `receiptId` の無い単発の取引・コメント・プラン・固定費の通知は**従来どおり即送信**（遅延なし）。

### 12.5 明細を直したらチャットに「変更履歴」を残す（v0.2.98 で追加）

たくはるカレンダーの「〇〇が予定を変更しました（時刻・場所）」と同じ仕組みを明細に入れた。
**編集通知はこの変更履歴コメント一本に統一**し、「何が変わったか」まで通知本文に載せる。

- **書き出し（アプリ側）**: 編集の入口は2つだけ。
  | 編集画面 | 書き込み先 | 対象項目 |
  |---|---|---|
  | `AddTransactionScreen`（単品編集） | `transactions/{txId}/comments` | 金額・品名・カテゴリ・日付・支払い・お店・払った人・個人わく |
  | `ReceiptEditScreen`（レシートまとめ編集） | `receipts/{rid}/comments` | 共通項目は1回だけ＋品目ごとの変更／追加／削除 |
  差分は `lib/data/tx_diff.dart` の `txDiff()`。`TxField` で「レシート共通項目
  （`kTxCommonFields`）」と「品目ごとの項目（`kTxItemFields`）」を出し分ける。
  変更ゼロなら**何も書かない**（＝通知も飛ばない）。
- **データ**: コメントdocに `kind: 'log'` を持たせる（既存＝会話は `kind` 無し＝`comment` 扱い）。
  **`commentCount` は増やさない**（💬バッジは会話用のまま）。
- **表示（`comment_thread.dart`）**: `kind='log'` は吹き出しではなく**中央のグレー帯**（カレンダーと同じ）。
- **通知（`notifier.py`）**: `_handle_cm` が `kind='log'` を検知 →
  `「〇〇が記録を直したよ ✏️」`／本文＝変更点（例 `個人わく なし → たく`）。
  tag は `tx:<txId>` / `receipt:<rid>` ＝記録通知と同じ枠に上書き。ON/OFFは記録系(`tx`)のトグル。
- **⚠ 取引の MODIFIED 監視は廃止した**。以前は Firestore の更新を見て「記録を修正したよ」を送っていたが、
  ①`personalFor`（個人わく）を見ていないので**個人わくを変えても通知が飛ばなかった**
  ②`receiptUrl` の後付けやカテゴリ自動修復など**内部的な書き換えでも通知が飛びうる**、の2つの穴があった。
  変更履歴コメント基点に変えて両方解消。
- **同時に直したバグ**: `notifier.py` が `category.major` を読んでいたが、実データは
  `categoryMajor`（フラット）なので**常に空文字**だった → `categoryMajor` に修正。
  レシートのチャットへのコメント通知が `txId=receiptId` で飛んでいて**タップしても開けなかった**
  → `receiptId` を送るよう修正（tag も `receiptcomment:<rid>`）。
