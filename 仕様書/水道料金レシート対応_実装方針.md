# 水道料金レシート対応 実装方針（たくはるファイナンス）

> 対象アプリ: **たくはるファイナンス**（`apps/takuharu_finance`）
> 起票日: 2026-08-10 / ステータス: **実装前・方針確定済み（実装はメイン開発機で行う）**
> 発端の要望:
> 「レシートの記録で水道料金の登録ができるようにしたい。
> 　そして、使用量・水道料金・下水道使用料金とかの内訳もついでに載せられるようにしたい」

---

## 0. 決定事項（ユーザー合意済み）

| 論点 | 決定 |
|---|---|
| 内訳データの持ち方 | **構造化フィールドで持つ**（将来「使用量の月別推移グラフ」まで見据える）。memo文字列で済ませない。 |
| 対象範囲 | **まず水道だけ**。電気・ガスは後日、同じ器で拡張できる設計にしておく（実装は水道のみ）。 |

---

## 1. ゴール（このタスクで「できるようになる」こと）

1. レシート記録フロー（カメラ）で **水道の検針票／請求書を撮ると、水道料金として登録できる**。
   - 品目は「水道料金」「下水道使用料」の2件に自動分割、カテゴリ＝**光熱費**、合計は請求金額に自動一致。
2. その登録に **使用量(m³)・前年同期・使用期間** が構造化データとして紐づき、
   レシート詳細の「内訳」に `💧 使用量 31m³（前年 32m³）／期間 6/11〜8/10` のように表示される。
3. 使用量は構造化フィールドなので、**後日「使用量の推移グラフ」を作れる土台**になっている
   （今回はデータを貯める所まで。グラフ画面は別タスク）。

### 非ゴール（今回やらない）
- 電気・ガスの使用量対応（器だけ汎用にしておくが実装しない）。
- 使用量の推移グラフ画面そのもの（データが貯まってから別タスク）。
- 手入力フロー（add_transaction_screen）側の使用量入力。レシート経由のみ。

---

## 2. 現状の作り（把握済み・前提）

- **1レシート = 同じ `receiptId` を持つ複数 `core.Transaction`**。1品目 = 1取引。
- レシート詳細（`receipt_detail_screen.dart`）の「内訳」は、その品目取引を金額付きで並べたもの。
- OCR（`data/receipt_ocr.dart`）は Gemini で `amount / date / store / category / items[]` を抽出。
  食費レシート前提の作りだが、`items` に「水道料金」「下水道使用料」を出せば **金額の登録自体は今でも一応通る**。
- `core.Transaction.amount` は **`int`（円）のみ**。使用量31m³のような **非金額データを入れる箱が無い** ← 今回の肝。
- `memo` フィールドは model には有るが、たくはるのレシート系では未入力・未表示。

### 実データ（名古屋市上下水道局・検針票／口座振替収書）
```
使用期間: 令和8年6月11日 〜 令和8年8月10日（期別 R8.7-R8.8）
今回指示値135 / 前回指示値104 / 今回使用量 31m³ / 参考:前年同時期 32m³
水道料金 3,668円（うち消費税333円）
下水道使用料 2,887円（うち消費税262円）
ご請求金額 6,555円
口座振替日: 令和8年9月7日
```
→ 期間の和暦は西暦へ（令和8年＝2026）。

## 3. データモデル変更（`packages/finance_core`）

> **additive・後方互換のみ**。既存データ・futa/haru のビルドを壊さない。

### 3-1. 新クラス `UsageDetail`（使用量メタ）
`packages/finance_core/lib/src/models/usage_detail.dart` を新設し、`finance_core.dart` で export。

```dart
/// 検針票などの「使用量」メタ情報（水道・将来は電気/ガス）。
/// 金額の内訳は品目Transactionで表すので、ここは非金額のメタに絞る。
class UsageDetail {
  final double? amount;      // 今回使用量（例 31）
  final String unit;         // 単位 'm3' / 'kWh'（水道は 'm3'）
  final double? prevAmount;  // 前年同期の使用量（例 32）。無ければ null
  final DateTime? periodFrom;// 使用期間 開始
  final DateTime? periodTo;  // 使用期間 終了
  final String kind;         // 種別 'water'（将来 'electricity' / 'gas'）

  const UsageDetail({
    this.amount, this.unit = 'm3', this.prevAmount,
    this.periodFrom, this.periodTo, this.kind = 'water',
  });

  Map<String, dynamic> toJson() => {
    if (amount != null) 'amount': amount,
    'unit': unit,
    if (prevAmount != null) 'prevAmount': prevAmount,
    if (periodFrom != null) 'periodFrom': periodFrom!.toIso8601String(),
    if (periodTo != null) 'periodTo': periodTo!.toIso8601String(),
    'kind': kind,
  };

  factory UsageDetail.fromJson(Map<String, dynamic> j) => UsageDetail(
    amount: (j['amount'] as num?)?.toDouble(),
    unit: j['unit'] as String? ?? 'm3',
    prevAmount: (j['prevAmount'] as num?)?.toDouble(),
    periodFrom: j['periodFrom'] != null ? DateTime.tryParse(j['periodFrom']) : null,
    periodTo: j['periodTo'] != null ? DateTime.tryParse(j['periodTo']) : null,
    kind: j['kind'] as String? ?? 'water',
  );

  UsageDetail copyWith({...}); // 全項目 nullable で素直に
}
```

### 3-2. `Transaction` に `usage` を追加
`transaction.dart` に以下を **追記のみ**：
- フィールド: `final UsageDetail? usage;`
- コンストラクタ引数に `this.usage,` を追加（任意）
- `toJson`: `if (usage != null) 'usage': usage!.toJson(),`
- `fromJson`: `usage: j['usage'] != null ? UsageDetail.fromJson(Map<String,dynamic>.from(j['usage'])) : null,`
- `copyWith`: `UsageDetail? usage,` を引数に足し、`usage: usage ?? this.usage,`。
  ※ **クリア用に `bool clearUsage = false` も足す**（personalFor と同じ流儀。編集で使用量を消せるように）。

### どの取引に `usage` を載せるか
- 水道レシートの **「水道料金」品目の取引** に載せる（＝そのレシートの代表1件）。
- 詳細/編集画面では `members.firstWhereOrNull((t) => t.usage != null)` で拾って表示・編集する。
- Firestore はスキーマレスなので既存ドキュメント互換。**セキュリティルールの変更不要**（同コレクション内フィールド追加のみ・要確認）。

## 4. OCR変更（`apps/takuharu_finance/lib/data/receipt_ocr.dart`）

### 4-1. `ReceiptResult` に使用量を追加
```dart
class ReceiptResult {
  ... 既存 ...
  final UsageDetail? usage; // 水道等の使用量メタ（無ければ null）
}
```

### 4-2. プロンプト追記（水道検針票を判定して抽出）
`_prompt()` の JSON スキーマに `water` ブロックを追加し、ルールを1段落足す：

```
// JSONに追加するキー
"water": {
  "isWaterBill": true/false（水道・上下水道の検針票/請求書ならtrue。違えばfalseにしてこのブロックの他は無視）,
  "usage": 今回使用量の数値（m³。例 31。読めなければ null）,
  "prevUsage": 前年同時期の使用量（例 32。無ければ null）,
  "periodFrom": "YYYY-MM-DD（使用期間の開始。和暦→西暦）",
  "periodTo": "YYYY-MM-DD（使用期間の終了）",
  "waterCharge": 水道料金の税込額（例 3668）,
  "sewerCharge": 下水道使用料の税込額（例 2887）
}
```
追加ルール：
- 水道/上下水道の検針票・請求書なら `water.isWaterBill=true`。このとき
  `items` は必ず **「水道料金」(price=waterCharge)** と **「下水道使用料」(price=sewerCharge)** の2件、
  各 `category="光熱費"`、`amount`＝ご請求金額（合計）、`store="水道料金"` とする。
- 和暦（令和8年＝2026）は西暦に直す。使用量は消費税・金額と混同しない（m³ の数値）。

### 4-3. パース
- `parsed['water']` を読み、`isWaterBill==true` かつ `usage`/`period` が取れたら
  `UsageDetail(amount, unit:'m3', prevAmount, periodFrom, periodTo, kind:'water')` を作って `ReceiptResult.usage` に。
- items が空でも water から `[水道料金, 下水道使用料]` を組み立てるフォールバックを入れる（OCRブレ対策）。
- `store` が空なら「水道料金」を既定に。

## 5. UI変更（3画面）

### 5-1. `receipt_split_screen.dart`（レシート初回登録）
- `widget.result.usage != null` のとき、品目リストの下に **「💧 使用量」カード** を出す。
  - 編集可: 使用量(m³) / 前年同期(m³) / 使用期間（from〜to、任意でDatePicker）。
  - 初期値は OCR の `usage`。
- `_save()`：作った txns のうち **「水道料金」品目（先頭 or description一致）** に
  `usage: _usageEdited` を載せて保存。他品目は usage=null。
- 既存の差額調整ロジックはそのまま（水道は外税表記でも合計一致するので adj=0 になる想定）。

### 5-2. `receipt_edit_screen.dart`（登録済みレシートの再編集）
- `widget.members` から `usage != null` の1件を拾い、同じ **「💧 使用量」カード** を出す。
- 保存時、水道料金品目の `copyWith(usage: ..., clearUsage: 消したとき)` で反映。

### 5-3. `receipt_detail_screen.dart`（詳細表示）
- `_header()` の「内訳」直前 or 直後に、`members` に `usage` があれば1行差し込む：
  ```
  💧 使用量 31m³（前年 32m³）
  期間 2026/6/11〜2026/8/10
  ```
  - 前年比があれば `▲1m³` 等の増減も添えると「消費感を肌で感じる」思想に合う（任意）。
- 既存の金額内訳（水道料金/下水道使用料の2行）はそのまま。

### エントリーポイント
- 新規導線は**不要**。既存のレシート撮影フロー（`receipt_flow.dart` → `ReceiptSplitScreen`）で水道検針票を撮ればそのまま乗る。
- 任意で record_menu に「水道・光熱の検針票もOK」の一言ヒントを足してもよい（必須でない）。

## 6. 集計・整合への影響

- 金額（水道料金＋下水道使用料＝光熱費）は **品目Transactionのまま**なので、
  ホーム/分析/カテゴリ内訳などの既存集計に**そのまま乗る**（集計コード変更不要）。
- `usage` はメタ情報で **金額集計に一切影響しない**（`effectiveAmount` 等に絡めない）。

## 8. 地雷・注意点

- **core変更は3アプリに波及**。フィールドは必ず nullable・toJsonは条件付き・fromJsonは null安全。破壊的にしない。
- **Firestoreはスキーマレス**なので既存データは `usage` 無しで普通に読める。ルール変更は原則不要（`firebase/` 配下を一応確認）。
- **和暦→西暦**：令和8年＝2026。OCRプロンプトで明示済みだが、パース側でも `DateTime.tryParse` 失敗をnull許容に。
- **使用量と金額の取り違え**：31（m³）と 3,668（円）を混同しないようプロンプトで釘を刺す。
- **合計一致**：水道は「水道料金＋下水道＝請求額」で差額0のはず。差額調整カードが余計な行を足さないか実機確認。
- **GEMINI_API_KEY**：ビルド時 `--dart-define=GEMINI_API_KEY=$(cat gemini.key ...)`（key は `apps/takuharu_finance/gemini.key` に存在確認済み）。Web版はOCR不可のまま（`available==false`）。
